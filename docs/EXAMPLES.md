# 场景规则与扩展

默认规则配置为 `generic`。在 `monitor/rules.local.json` 中选择一组适合目标群的规则；模板的所有规则默认关闭。一个实例只配置一个群，不能把多个群 ID 拼进同一字段。

## 学校通知

关注“考试安排”“报名截止”“截止报名”“提交材料”“停课通知”；排除“测试消息”“已取消”。这能匹配相应字面内容，不会推断所有“重要通知”，也不自动识别截止时间并建立日程。需要增加“家长会”“缴费”等内容时，把词加入本地列表并测试正反例。

## 特价与补货

关注“超好价”“超好忦”“限时优惠”“补货”；排除“已结束”“售罄”。这适用于不限品类的消息跟踪，不声称已经计算商品到手价、库存或性价比。异体字或拆字写法需要在 `any_keywords` 中列出实际关注的写法。

## 团队与社区

团队可关注“会议改期”“提交周报”“发布窗口”；社区可关注“停水通知”“活动变更”。每条规则有自己的显示名称、启用状态及排除词，按文件顺序选第一条命中，避免同一消息同时发多封邮件。

规则仅执行固定的字符串匹配。未知字段会报错，因此不要把 `regex`、任意脚本或自然语言 prompt 填进 JSON 并期待它运行。复杂分类可实现新的适配器，但应单独测试和说明能力。

## 可选：结构化商品价格示例

早期实现包含一个 `protein_deals` 示例适配器，位于 `monitor/deals.py`。在 `settings.local.json` 中显式设置 `rule_profile: "protein_deals"` 才会启用：ON 单件 5 磅人民币报价严格小于 580 元、熊猫单件 5 磅严格小于 400 元，以及相应“超好价”写法提醒。

这些是该示例适配器的固定业务条件，不是通用 JSON 规则的价格表达式。通用模式不会自动启用它；如需任意商品价格、日期、报名对象等结构化规则，应实现专门解析和邮件复核，并加入边界测试。保留这个适配器是为了说明如何接入具体业务，项目本身不限定于蛋白粉或特价群。

## 扩展入口

1. 在新适配器中把文字转为事件结构，或扩展经过验证的配置模式。
2. 在 `matcher.py` 显式选择适配器，不根据群消息动态加载代码。
3. 在 `outlook_mailer.py` 添加相应的发送前复核，确保失效规则、错误范围和不充分证据不能进入邮件。
4. 覆盖正反例、边界、去重、恢复和消息片段最小化；通知通道必须由用户明确选择。

多群、语义分类、Webhook、SMTP、手机通知等都需要额外实现，目前不能把它们当已有能力写进部署完成报告。
